## A3. STUDENTS, ADMISSIONS, INVITATIONS, DOCUMENTS
1. Admissions (/admin/admissions): the applications inbox from the public Apply form (applicant details, course, category, professional title and registration number, consent timestamp). The Admin picks an application and clicks "Create student" with the data prefilled, or registers a walk-in student with the same form. Fields: full name as on ID, email (unique), phone (+256), course and intake, category with eligibility checks, date of birth, gender, district, highest qualification, optional ID number stored encrypted, emergency contact. Duplicate checks by email and phone. CSV bulk import with preview and per-row validation.
2. On creation the system generates the registration number (per course and year, as above) and the record goes to the Principal as an admission approval; there is no login yet. When the Principal approves, the student receives the email (demo mode shows it in /dev/mail) that an account was created, with a set-password link, and becomes ACTIVE after setting the password. Statuses visible to the Admin: application received, record created, awaiting Principal, approved, invitation sent, accepted, rejected (with the reason), expired.
3. Invitations (/admin/invites): list of students not yet accepted with days waiting; Resend (new link, old link invalid), revoke, send a password reset link to an ACTIVE student (never see or set a password); rate limits; each action audited and the student notified.

Students (/admin/students): list with search, filters (course, intake, class, status, payment phase), pagination; student detail with profile, registration number, class, documents, attendance, payment phase status (view only), approval history; edit phone, address, emergency contact and corrections to details (the registration number, email and full name changes need a reason and are audited); deactivate, archive and restore. CSV export audit logged.
5. Student Documents (/admin/documents, replace the "Coming Soon" page): upload, view, replace and archive documents per student (national ID copy, certificates, photo, application form); allowed types and size limits; stored privately in the database or S3-compatible storage with signed expiring URLs; a "missing documents" report; only the Admin, Principal and Director can view them; every view and upload audit logged.

Tests (three contexts): applicant submits the form, the Admin creates the student, the number follows the per-course sequence, the Principal approves, the email arrives, the student sets a password and logs in; resend invitation invalidates the old link; the Admin cannot create an Instructor or Director account; document upload and signed URL expiry; duplicate email blocked.
